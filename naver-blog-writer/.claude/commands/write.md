# /write

사용자가 사진(input/photos/), 영상(있으면 input/videos/), 소재 정보, 한줄 메모를 주면 다음 순서로 진행한다.

## 1. 입력 확인

- input/photos/ 의 사진을 모두 Read로 실제로 보고 내용을 파악한다 (파일명만 보고 추측하지 않는다).
- data/photo-guide.md 체크리스트와 대조해 빠진 필수 컷이 있으면 사용자에게 알린다 (지어내지 않는다).
- input/videos/ 에 영상이 있으면 draft의 video 필드에 넣을 준비를 한다 (title 40자 이내 — video.title > 글 제목 > 기본값 순).

## 2. 협찬 여부 확인 (공정위 표시광고법 — 생략 불가)

- 이번 소재가 협찬/체험단 대가를 받은 것인지 메모에 없으면 반드시 질문한다.
- 협찬이면 data/sponsored-disclosure.md에서 대가 유형에 맞는 문구(업체 지정 문구가 있으면 그것 우선)를 글 상단 첫 블록(quote 아닌 일반 text)에 넣는다.
- "내돈내산", "광고 아님" 등 거짓 부인 표현은 협찬 글에 절대 쓰지 않는다.

## 3. 사실 대조

- data/profile.md에 없는 정보는 절대 지어내지 않는다. 필요하면 사용자에게 묻는다.
- 가격은 "상담 후 안내"로만 표현한다 (숫자 단정 금지). 특정 휴무 날짜를 못 박지 않는다.
- 원장/강사 경력이 필요한데 profile.md에 "미확인"이면 authority-lines.md의 "경력형"은 쓰지 않는다.

## 4. 페르소나 설계

- data/profile.md의 "타겟 세그먼트" 중 이번 글에 맞는 1명을 구체적으로 정의한다 (지역·나이·직책·상황·감정).
- 그 사람에게 말 걸듯 쓴다. 검수 시 페르소나도 함께 보고한다.

## 5. 글쓰기 공식 적용 (CLAUDE.md 참조)

- 메인 키워드(지역명 포함) 1개 + 서브 2~3개.
- 첫 문단 Yes-set + 결론 예고, 둘째 문단 권위 한 줄(authority-lines.md에서 변형).
- 후킹 패턴(손실회피/현장몰입/반전/공감)은 매번 다르게.
- 홍보 냄새 제거 규칙(업체명 본문 3회 이내, CTA에서만 1회, 연락처 전체 1회) 준수.
- 가독성 규칙(한 문장=한 줄, 한 블록 3~5줄, 300~400자마다 리듬 파괴 장치, 인용구 2~4개) 준수.
- 사진은 스토리 순서로 배치(파일 순서 아님), 캡션 절반 정도에만 키워드 배치.

## 6. 개인정보 모자이크 확인

- 사진에 식별 가능한 타인 얼굴·차량 번호판·전화번호가 있으면 scripts/mosaic.js로 처리하고, 처리본을 Read로 반드시 확인한다.
- 화자 본인 얼굴도 기본 모자이크 (공개 명시 시만 예외).
- 처리 내역(몇 장·몇 영역·사유)을 검수 보고에 포함한다.

## 7. 초안 JSON 작성

drafts/ 에 아래 포맷으로 저장한다.

```json
{
  "title": "...",
  "tags": ["..."],
  "place": { "query": "...", "name": "..." },
  "video": { "path": "input/videos/...", "title": "..." },
  "blocks": [
    { "type": "text", "text": "..." },
    { "type": "subtitle", "text": "..." },
    { "type": "image", "path": "input/photos/_mosaic/... 또는 input/photos/...", "caption": "..." },
    { "type": "quote", "text": "..." },
    { "type": "divider" }
  ]
}
```

## 8. 사용자 승인

- 초안 전문(제목/본문/페르소나/모자이크 처리 내역/업종 체크리스트 대조 결과)을 보여주고 승인을 받는다.
- 자가 질문: "모바일에서 인용구와 소제목만 훑어도 핵심이 전달되는가?"
- 승인 전에는 절대 naver_draft.js를 저장 모드로 실행하지 않는다.

## 9. 실행

- 먼저 `node scripts/naver_draft.js drafts/<파일>.json --dry-run` 으로 셀렉터 확인.
- 문제 없으면 `node scripts/naver_draft.js drafts/<파일>.json` 으로 실제 임시저장까지 진행.
- 실행 로그의 "자동 처리 결과" 블록을 확인한다.

## 10. 이중 검증

- 스크린샷 + 텍스트 덤프(drafts/verify_*.txt)를 초안과 전문 대조한다.
- 불일치하면 성공 보고 금지 — 원인을 찾아 수정 후 재실행한다.

## 11. 안내

- "자동 처리 결과"에서 ❗수동 필요로 찍힌 항목만 사용자에게 안내한다.
- 추가로 안내: 타겟 활동 시간대 발행, 발행 후 24시간 수정 금지, 주 2~3회 주기(하루 2건 이상 금지), 협찬 표기 육안 확인.
- 디버깅 재실행으로 "저장 글"에 실패본이 쌓였을 수 있으면 사용자에게 직접 정리를 안내한다 (자동 삭제 금지).
